공격자는 티빙 개발자가 코드 저장소(GitHub)에 올려 둔 코드에서, 그 안에 그대로 적혀 있던 클라우드 접속 키를 손에 넣었습니다. 이 키 하나면 서버와 저장소, 고객 정보가 담긴 데이터베이스까지 모두 열 수 있었습니다. 공격자는 곧장 데이터베이스에 직접 들어가 내용을 꺼내 보고 고치기까지 했습니다. 자료를 훔쳐본 정도가 아니라 회사 시스템의 조종간을 통째로 넘겨준 셈입니다.

결과. 5월 30일 저녁, DB 서버 CPU가 100%까지 치솟으며 이상이 감지됐습니다. 그런데 침해 사실을 확인한 것은 이튿날인 31일 오후였고, 법이 정한 신고 기한 24시간을 겨우 지켜 6월 1일 KISA에 신고했습니다. 이름·생년월일·전화번호·이메일·CI 같은 이용자 정보가 유출됐고, 초기엔 최대 1,300만 명대로 관측됐지만 이후 조사에서 규모는 약 1,953만 명으로 확정됐습니다. 티빙은 AWS 키를 즉시 폐기하고 GitHub 자격증명을 교체했지만, 2026년 8월 현재 과학기술정보통신부의 제재 수위 발표를 앞두고 있어 사건은 아직 진행 중입니다.

일본 · 협력사가 GitHub에 올린 앱 코드

토요타 협력사 개발자가 2017년 커넥티드카 앱 'T-Connect'의 소스 코드 일부를 GitHub에 올리면서 공개 설정으로 두었습니다. 이 코드 안에는 고객 데이터 서버에 접속하는 키가 들어 있었습니다.

결과. 약 5년이 지난 2022년에야 발견됐고, 그동안 고객 약 29만 6천 명의 이메일 주소와 관리번호가 노출될 수 있는 상태였습니다. 실제 악용은 확인되지 않았지만, 키 하나가 5년간 인터넷에 떠 있었다는 사실만으로 토요타가 공식 사과를 해야 했습니다.

공개 저장소에 올라온 키는 사람보다 봇이 먼저 찾습니다. 자동 스캔 봇이 GitHub를 쉴 새 없이 훑어, 올라온 지 몇 분 만에 키를 가져다 씁니다. 가장 흔한 결말은 이렇습니다. 남의 클라우드에 몰래 들어가 가상화폐를 채굴하고, 하룻밤 사이 수천만 원짜리 요금을 원래 주인에게 떠넘깁니다. AI에게 시켜서 만든 코드를 GitHub에 올릴 때도 마찬가지입니다. 올리기 전에 키나 비밀번호가 코드 안에 그대로 적혀 있지 않은지 반드시 확인하세요.

미국 델라웨어 형평법원 · 한국 기업 분쟁

크래프톤은 2021년 인수한 게임사 언노운월즈에 최대 2억 5천만 달러의 성과급을 약속했습니다. 그런데 '서브노티카 2'의 흥행이 눈앞에 보이자, 그 성과급을 주지 않으려고 테드 길 CEO를 비롯한 경영진을 해임했다는 것이 이 소송의 요지입니다.

법원 판단. 경영진이 약 한 달간 ChatGPT와 나눈 해임 전략 대화가 그대로 법정에 제출됐습니다. 회사는 "단순 정보 조회"라 했지만, 법원은 대화가 한 달이나 이어진 점을 들어 해임을 '고의적 계약 위반'으로 보고 CEO 복직과 성과급 기한 연장을 명령했습니다. 김창한 대표가 일부 대화를 직접 삭제했다고 인정했지만, 공유된 전략 문서가 남아 드러났습니다. 회사가 AI에 물어본 내용도 변호사와 나눈 이야기처럼 보호받지는 못합니다.

저작권 소송의 증거가 될 대화가 지워질까 우려한 왕(Ona Wang) 치안판사는, OpenAI에 삭제 예정이던 출력 로그를 앞으로도 지우지 말고 전부 보존하라고 명령했습니다. 무료와 Plus, Pro, Team 이용자는 물론 데이터 보존 예외 계약이 없는 API 고객까지 대상이었습니다. 사용자가 직접 지운 대화도, 30일 뒤 자동으로 사라지던 임시 대화도 예외 없이 남았습니다. 여기서 제외된 쪽은 Enterprise와 Edu, 그리고 데이터를 남기지 않기로 따로 계약한 API 고객뿐이었습니다.

5 AI가 직접 일을 실행할 때 읽기·쓰기·실행 권한

코워크와 클로드 코드에서는 AI가 직접 파일을 고치고 명령을 실행합니다. 그만큼 편하지만, "확인 없이 알아서 해"로 맡겨 두면 되돌리기 어려운 일이 벌어집니다.

읽기 권한 안전

파일을 보고 요약하고 답하는 단계입니다. 내용을 바꾸지 않아 가장 안전합니다. 평소 작업 대부분은 여기서 끝납니다.

쓰기·실행 권한 주의

파일을 수정·삭제하거나 명령을 실행하고 메일을 보냅니다. 결과가 실제로 바뀌므로 한 건씩 확인하며 진행하는 편이 안전합니다.

자동 승인 모드 위험도 높음

매번 묻지 않고 AI가 알아서 실행하게 두는 모드입니다. 빠르지만 파일 대량 삭제, 외부 전송, 잘못된 배포가 확인 없이 일어날 수 있습니다. 익숙하지 않다면 자동 승인은 켜지 않는 편이 좋습니다. 꼭 써야 한다면, 백업이 있고 되돌릴 수 있는 폴더에서만 씁니다.

중요한 폴더는 사본을 떠서 작업하고, 언제든 이전 상태로 되돌릴 수 있게 해 두세요.

위험한 작업은 한 번 더 확인하세요. 전체 삭제, 외부로 보내기, 권한 변경을 AI가 제안하면 실행하기 전에 무엇을 어디에 하는지 한 줄로 되짚어 보세요. "되돌릴 수 있나"가 판단 기준입니다.
실제로 터진 사고 "확인하고 해"라는 지시를 무시하고 폭주한 일

자동 실행의 위험은 이미 현실에서 확인됐습니다. 개발 도구의 자동 승인 설정 하나가 컴퓨터 전체를 내준 적이 있고, AI 안전을 연구하는 전문가조차 자기 메일을 통째로 잃을 뻔했습니다.

결과. 설정이 한번 켜지면 그다음부터는 사용자 확인 없이 어떤 셸 명령이든 실행할 수 있어, 윈도우와 맥, 리눅스를 가리지 않고 개발자 PC 전체를 장악할 길이 열렸습니다. 저장소 하나를 열어 보는 것만으로 다음 사람에게 옮겨 간다는 점에서 '웜(worm)형' 취약점으로 불렸습니다. 마이크로소프트는 2025년 8월 정기 패치로 이를 막았습니다. 묻지 않고 실행하는 설정이 왜 위험한 기본값인지 보여 준 사례입니다.

결과. 그런데 2026년 6월 열린 실제 재판에서 배심원단은 평결에 이르지 못해 미스트라이얼(재판 무효)이 선언됐습니다. 배심원 12명 중 10명이 무죄 쪽이었던 것으로 알려져, 검찰이 제시한 ChatGPT 대화 기록이 배심원 다수를 설득하지는 못했습니다. 재심리는 2026년 10월 19일로 예정돼 있습니다. AI 채팅 기록이 증거로 제출된다고 해서 곧바로 유죄로 이어지는 것은 아니라는 것도 이 사건이 보여 줍니다.

지우면 그만이라고 생각하기 쉽지만, 법원이 보존을 명령하면 회사는 지워질 기록까지 따로 떼어 보관해야 합니다. 그러니 AI 채팅창은 혼자 보는 메모장이 아니라, 언젠가 남이 읽을 수도 있는 기록이라고 생각하는 편이 안전합니다.

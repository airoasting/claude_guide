오픈소스 AI 에이전트 · 메일에 자동 접근

OpenClaw는 메일과 메신저, 파일을 모두 열어 보며 24시간 스스로 일을 처리하는 공개 AI 에이전트입니다. 처음 이름은 'Clawdbot'이었는데, Anthropic이 상표권 문제를 제기하면서 'Moltbot'을 거쳐 지금 이름이 됐습니다. 보안 연구진은 메일 본문에 숨긴 명령만으로 이 에이전트를 조종할 수 있음을 시연했습니다.

결과. 사용자가 "메일 확인해줘"라고 시키는 순간, 에이전트는 숨은 지시를 진짜 명령으로 받아들여 기기의 개인 키와 메일 내용을 외부로 빼냈습니다. 사람이 한 번도 승인하지 않았는데 벌어진 일입니다. 메일·문서를 자동으로 읽는 AI에게는, 평범해 보이는 한 줄이 곧 명령이 됩니다.

Vercel 환경변수 유출 사고

미국 · 직원이 OAuth로 연결한 외부 AI 도구가 침입 통로

웹 배포 플랫폼 Vercel의 직원 한 명이 외부 AI 도구(Context.ai)를 회사 구글 계정에 OAuth로 연결해 두었습니다. 그 외부 도구의 OAuth 토큰이 털리자, 공격자는 그 연결을 타고 직원의 구글 워크스페이스 계정을 장악한 뒤 Vercel 내부 환경까지 들어왔습니다. 회사를 정면으로 해킹한 것이 아니라, 직원이 무심코 연결해 둔 도구 하나가 문을 열어 준 것입니다.

결과. 공격자는 '민감'으로 표시해 두지 않아 암호화 없이 그대로 읽히는 설정값(API 키, 각종 토큰, 데이터베이스 비밀번호, 서명 키)을 빼냈습니다. 한 위협 인텔리전스 업체는 공격자가 고객 API 키와 DB 데이터를 해커 포럼에 약 200만 달러에 팔겠다고 내놓았다고 전했지만, 이는 아직 확인되지 않은 주장입니다. Vercel은 소스 코드 유출은 없었다고 공식 부인하면서도 영향받은 고객의 자격증명을 즉시 교체하고 환경변수를 '민감'으로 설정하라고 공지했습니다. '수백 명, 여러 조직'이라는 숫자는 Vercel이 입은 피해가 아닙니다. Context.ai를 함께 쓰던 업계 전체가 위험해질 수 있다는 뜻이었고, Vercel 자신의 피해는 '제한된 일부 고객'이라고만 밝혔습니다. 연결을 하나 허용하는 것은 곧 회사 문을 하나 열어 두는 일입니다.

자동 실행 · 실행 권한
5 AI가 직접 일을 실행할 때 읽기·쓰기·실행 권한

코워크와 클로드 코드에서는 AI가 직접 파일을 고치고 명령을 실행합니다. 그만큼 편하지만, "확인 없이 알아서 해"로 맡겨 두면 되돌리기 어려운 일이 벌어집니다.

읽기 권한 안전

파일을 보고 요약하고 답하는 단계입니다. 내용을 바꾸지 않아 가장 안전합니다. 평소 작업 대부분은 여기서 끝납니다.

쓰기·실행 권한 주의

파일을 수정·삭제하거나 명령을 실행하고 메일을 보냅니다. 결과가 실제로 바뀌므로 한 건씩 확인하며 진행하는 편이 안전합니다.

자동 승인 모드 위험도 높음

매번 묻지 않고 AI가 알아서 실행하게 두는 모드입니다. 빠르지만 파일 대량 삭제, 외부 전송, 잘못된 배포가 확인 없이 일어날 수 있습니다. 익숙하지 않다면 자동 승인은 켜지 않는 편이 좋습니다. 꼭 써야 한다면, 백업이 있고 되돌릴 수 있는 폴더에서만 씁니다.

중요한 폴더는 사본을 떠서 작업하고, 언제든 이전 상태로 되돌릴 수 있게 해 두세요.

위험한 작업은 한 번 더 확인하세요. 전체 삭제, 외부로 보내기, 권한 변경을 AI가 제안하면 실행하기 전에 무엇을 어디에 하는지 한 줄로 되짚어 보세요. "되돌릴 수 있나"가 판단 기준입니다.
실제로 터진 사고 "확인하고 해"라는 지시를 무시하고 폭주한 일

자동 실행의 위험은 이미 현실에서 확인됐습니다. 개발 도구의 자동 승인 설정 하나가 컴퓨터 전체를 내준 적이 있고, AI 안전을 연구하는 전문가조차 자기 메일을 통째로 잃을 뻔했습니다.

깃허브 코파일럿, 숨은 명령 한 줄로 '전체 승인' 모드가 켜지다

깃허브 코파일럿 · 비주얼 스튜디오 코드(CVE-2025-53773, 공식 표기는 Visual Studio)

비주얼 스튜디오 코드에는 매번 묻지 않고 AI가 명령을 바로 실행하게 하는 '전체 승인' 설정이 있습니다. 연구진은 코드 주석이나 문서, 저장소 파일에 숨은 명령을 심어 두면 코파일럿이 그 설정 파일을 직접 고쳐 쓴다는 것을 보였습니다. 개발자는 평소처럼 코드를 봐 달라고 시켰을 뿐인데, AI가 제 손으로 제 안전장치를 꺼 버리는 구조였습니다.

결과. 설정이 한번 켜지면 그다음부터는 사용자 확인 없이 어떤 셸 명령이든 실행할 수 있어, 윈도우와 맥, 리눅스를 가리지 않고 개발자 PC 전체를 장악할 길이 열렸습니다. 저장소 하나를 열어 보는 것만으로 다음 사람에게 옮겨 간다는 점에서 '웜(worm)형' 취약점으로 불렸습니다. 마이크로소프트는 2025년 8월 정기 패치로 이를 막았습니다. 묻지 않고 실행하는 설정이 왜 위험한 기본값인지 보여 준 사례입니다.

02
멀티 페르소나로 개선하기
★★☆☆☆ 결과물: 다섯 역할이 채점하고 고친 스탑워치와 점수 변화표 약 20분
▼
프롬프트
방금 만든 스탑워치 화면을 아래 다섯 명이 함께 개선해줘. 각자 자기 역할의 기준으로만 보고, 다른 사람과 같은 지적은 하지 마. 블랙 · UI/UX 디자이너 (수행자) 나머지 네 명의 지적을 모아 화면을 직접 고친다. 무엇을 왜 바꿨는지 한 줄씩 남긴다. 레드 · QA 엔지니어 (이성 비평가) 기능이 맞게 작동하는지 본다. 시간 오차, 버튼을 연달아 누를 때, 랩 기록 순서, 새로고침했을 때. 실버 · 육상 경기 계측원 (분야 전문가) 실제 계측 장비 기준으로 본다. 1/100초 표시, 랩과 구간 구분, 기록 표기 방식, 빠진 기능. 블루 · 사용성 연구원 (공감 비평가) 처음 쓰는 사람이 어디서 멈칫하는지 본다. 버튼 이름, 지금 상태가 보이는지, 글자 대비, 누르기 쉬운 크기. 골드 · 트랙 코치 (실제 사용자) 운동장에서 휴대폰 한 손으로 선수 랩을 잰다. 햇빛 아래서 3초 안에 쓸 수 있는지 본다. 진행 순서 1. 블랙을 뺀 네 명이 각자 10점 만점 점수, 근거, 고칠 것 3개를 낸다. 2. 블랙이 지적을 중요한 순서로 정리해 직접 고친다. 3. 네 명이 다시 채점한다. 네 명 평균이 9.5점을 넘을 때까지 반복한다. 최대 3번. 4. 마지막에 역할별 점수가 처음과 끝에 어떻게 바뀌었는지 표로 보여줘.
기대 효과
답변 하나로 끝내지 않고 다섯 관점에서 검토한 뒤 스스로 고칩니다. 혼자 볼 때는 지나쳤던 문제가 드러납니다.

1. GitHub.com 아이디 생성 (크롬에서 로그인해 둔 상태로 진행) 2. New Repository 생성 3. AI에게 GitHub 로그인 요청 "GitHub CLI(gh)를 설치하고 gh auth login을 웹 브라우저 방식으로 실행해줘" 4. 화면에 뜬 여덟 자리 코드(XXXX-XXXX)를 복사 → 크롬이 열리면 코드를 붙여넣고 Authorize github 클릭 : 토큰이나 비밀번호를 AI에게 직접 줄 필요가 없음 5. ▼
이 실습의 순서
엑셀 파일 속 대상(매장, 메뉴, 공급사, 배달 플랫폼, 사건)과 그 관계를 AI에게 정리하게 합니다. 대상과 관계의 규칙이 온톨로지, 그 규칙대로 실제 대상을 이은 그림이 지식 그래프입니다. 1단계에서 온톨로지를 HTML로 저장하고, 2단계에서 같은 HTML에 지식 그래프를 더합니다. 파일에는 함정이 두 개 있습니다. 시트마다 같은 매장이 다른 이름으로 적혀 있고, 매출 항목에 상품이 아닌 배달비가 섞여 있습니다. AI가 이 함정을 알아채는지가 이 실습의 핵심입니다.

마인크래프트 같은 3D 블록 세계 만들기
★★★★★ 결과물: 고양이를 조종해 구슬을 모으는 3D 블록 게임 약 60분
▼
1단계 · 채팅에서 먼저

### 2026-08-29 (company-brain-practice 전면 재작성: 직접 만들기에서 공개 스킬 내려받아 돌리기로)

`company-brain-practice.html`을 **하네스를 직접 쓰는 실습에서 공개 스킬을 설치해 돌리는 실습으로** 바꿨다. 사용자 지시는 "샘플 데이터를 다운로드 받아서 LLM Wiki 스킬을 다운로드 받아 돌리게 하는 것"이었다.

**출처를 바로잡았다.** Karpathy 본인이 만든 LLM Wiki 스킬 저장소는 없다. 그는 [gist](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)로 방식만 공개했고, 스킬 구현은 전부 제3자다. 이 실습이 쓰는 것은 [Astro-Han/karpathy-llm-wiki](https://github.com/Astro-Han/karpathy-llm-wiki)(MIT, Agent Skills 규격)다. 페이지에도 "Karpathy 본인이 만든 스킬이 아니라, 그가 공개한 방식을 따라 만든 오픈소스"라고 명시했다.

**설계가 통째로 바뀌었다.** 기존은 `inbox/` + 4역할(정리가·편집자·사서·안내데스크 = `digest`·`update`·`catalog`·`ask`)이었다. 외부 스킬은 `raw/` + **3동작(Ingest·Query·Lint)**이다. 그래서 STEP 1~5와 flow-diagram, wf-steps, role-grid, toc-grid, pipeline-wrap을 전부 다시 썼다. `AGENTS.md`·`CLAUDE.md`·`wiki-config.md`를 만들게 하던 프롬프트 1·2와 `memory/` 폴더 개념은 삭제했다. 스킬 안에 규칙이 이미 들어 있기 때문이다.

**바뀐 STEP 4.** 4-A 폴더 만들기 → 4-B `npx skills add Astro-Han/karpathy-llm-wiki`(Node 없으면 ZIP 받아 `SKILL.md`·`references/`·`scripts/`를 스킬 폴더에 복사) → 4-C 도구 실행 → 4-D Ingest → 4-E Query → 4-F Lint → 4-G 주간 사이클. 저장소 안내문의 `npx add-skill`은 폐기된 옛 이름이라 `npx skills add`로 적었다(npm에 DEPRECATED 표시).

**샘플 자산도 구조를 맞췄다.** `docs/assets/company-brain/inbox/` → `raw/company/`(7개)로 옮기고, 인사평가 메모는 `sensitive-excluded/`(1개)로 뺐다. 이 스킬에는 **민감도 기준이 없다.** 예전에는 `wiki-config.md`의 민감도 기준이 대외비를 걸러 내는 것이 함정 3번의 정답이었는데, 이제는 사람이 `raw/`에 넣지 않는 것이 유일한 안전장치다. 페이지에도 그렇게 고쳐 적었다. zip 재생성(12KB), README도 새 구조로 다시 썼다.

**소요 시간 표기도 낮췄다.** 하네스를 직접 쓰지 않으니 첫 구축 2시간 → 40분, 주간 갱신 30분 → 20분.

**아직 남은 불일치.** `company-brain.html`(설명 편)과 `company-brain-tasks.html`(점검 편)은 여전히 4역할 기준으로 서술되어 있다. 실습 편만 3동작으로 갔으므로 세 페이지 사이 용어가 어긋난다. 다음 작업에서 맞춰야 한다.

### 2026-08-27 (mcp-examples 전면 개편: 스텝을 checklist 명령 목록 규격으로 교체)

`mcp-examples.html` 다섯 예제의 스텝 UI를 **`checklist.html`의 명령 목록 규격으로 통째로 갈아끼웠다.** 사용자가 checklist 1단계 화면을 스크린샷으로 주며 "이런 스타일로, 특히 체크리스트 누르면 가운데 선 그어지게"라고 지정했다. 범위는 다섯 예제 전부(같은 페이지에서 스텝 모양이 갈라지면 안 된다), 체크 상태는 저장하지 않는다(따라하기 예제이지 진도표가 아니다).

**바뀐 구조.** `<ol class="mcp-steps">`(번호 원 + 검은 `.prompt-box` 분리)에서 `<ul class="cmd-list">` 한 덩어리로 옮겼다. 항목 하나가 `.cmd-head`(체크박스 + ①번호 제목) · `.cmd-tail > .cmd-pill`(밝은 알약 + 오른쪽 복사 버튼) · `.cmd-why`(설명) · `.cmd-ok`(옅은 녹색 확인줄)를 품는다. 예전엔 명령과 그 설명이 서로 다른 블록으로 흩어져 있어서 어느 명령의 설명인지 눈으로 이어야 했다.

**단계 수: 드라이브 4 · 카카오 6 · DART 3 · 법령 5 · 텔레그램 9, 합계 27.** 체크박스 27개, 복사 가능한 명령 13개, 경로 안내 알약(`.cmd-pill-note`, 복사 버튼 없음) 6개.

**체크 동작은 checklist와 일부러 다르게 했다.** checklist는 `li.checked span` 선택자가 넓어서 명령 글자까지 선이 그어진다. 여기서는 **`.cmd-label`에만 선을 긋고** 나머지는 `opacity: 0.5`로 죽인다. 끝낸 단계라도 명령은 다시 읽어야 하기 때문이다. 제목을 눌러도 체크된다.

**같이 걷어낸 것.** `.mcp-steps`(번호 원 counter 포함) · `.mcp-addr-label` · `.prompt-box` · `.copy-btn` CSS와 `copyPrompt()`를 지웠다. `.mcp-steps` 아래에만 걸려 있던 `.step-warn` · `.step-row` · `a.pill-link.pill-block`은 그대로 두면 죽으므로 **`.cmd-item` 하위로 다시 걸었다.** 이게 이번 교체에서 가장 놓치기 쉬운 지점이다.

**함께 손본 텔레그램 카드 내용.** 안내 상자 셋(회사 계정 차단 · 봇 토큰 보안 · 실행이 안 된다면)을 옅은 녹색 `.mcp-green`으로 통일했다. 쓰이지 않고 남아 있던 `.mcp-done` 정의를 이름만 바꿔 되살린 것이다. 봇 토큰 안내는 토큰을 처음 쥐는 5번 밑으로 옮겼다. 문제 해결 줄에는 `.note-tag` 알약(`실행이 안 된다면` + 물음표 원 SVG)을 앞머리에 붙였고, 녹색 상자 안에서는 알약도 녹색으로 맞춘다.

**모바일.** `.cmd-list` 들여쓰기 38px를 0으로, `.cmd-pill`은 `flex-direction: column`으로 세워 복사 버튼을 아래로 내린다. 375px에서 가로 넘침 0 확인.

### 2026-08-27 (mcp-examples 텔레그램 예제: Bun 준비물 추가 + 설치 순서 교정)

`mcp-examples.html` 다섯째 예제(`#mcp-telegram`)를 7단계에서 **9단계**로 다시 짰다. 두 가지를 고쳤다.

**빠져 있던 준비물이 있었다. Bun이다.** 공식 플러그인 `telegram@claude-plugins-official`의 `.mcp.json`은 `"command": "bun"`으로 서버를 띄운다. Node가 아니라 Bun이다. 플러그인 README도 Prerequisites 첫 줄에 Bun을 적어 놨는데 이 페이지에는 없었다. 그래서 Bun이 없는 컴퓨터에서는 플러그인이 깔려도 봇이 붙지 않고, 원인이 화면에 안 보인다. 2번 단계로 신설했다.

**설치 명령은 `npm install -g bun` 하나로 갔다(사용자 판단).** 공식 스크립트는 맥(`curl -fsSL https://bun.sh/install | bash`)과 윈도우(`powershell -c "irm bun.sh/install.ps1|iex"`)가 갈라지는데, npm 방식은 둘이 같다. 이 페이지 1번이 이미 Node.js 설치라 npm이 보장되므로 OS 분기 안내를 통째로 뺄 수 있었다. npm 레지스트리 `bun` 패키지의 `os` 필드가 `darwin`·`linux`·`win32`를 모두 포함하는 것으로 확인했다. 단, npm으로 깐 Bun은 `bun upgrade` 대신 npm으로 올려야 한다.

**Bun이 필요한 범위도 확인해 뒀다.** 공식 마켓플레이스 289개 중 `.mcp.json`의 `command`가 `bun`인 것은 **telegram·discord·imessage·fakechat 넷뿐**이다. 전부 Anthropic이 만든 메시지 브리지 계열이다. 나머지는 원격 서버이거나 번들 서버가 없다. **그래서 `checklist.html` 1단계(필수 설치)에는 넣지 않았다.** 대부분의 수강생이 쓰지 않을 런타임을 첫 관문에 두면 이탈만 는다. 필요한 사람이 필요한 시점에 깔도록 이 예제 안에 뒀다.

**토큰 등록과 `--channels` 재실행의 순서가 뒤집혀 있었다.** 기존은 `--channels`로 켠 다음 `/telegram:configure`였다. 플러그인의 `configure` 스킬 문서에 **서버는 `.env`를 부팅할 때 한 번만 읽는다**고 적혀 있다. 그래서 옛 순서대로 하면 첫 `--channels` 세션에는 토큰이 없어 봇이 안 붙고, 결국 한 번 더 껐다 켜야 한다. 공식 README 순서(설치 → 토큰 → `--channels`)로 되돌렸다.

**1번은 Claude Code 설치다(사용자 지적).** 처음엔 Bun을 1번에 뒀는데, 이 예제는 터미널 전용이라 Claude Code가 먼저다. 1번을 `claude` 명령 확인과 `checklist.html#tip1` 링크로 올리고(`#level1`은 섹션 앵커라 스크롤만 하고, `#tip1`이라야 `initTipAnchors`가 설치 아코디언을 열어 준다), 옛 4번 항목 안에 숨어 있던 같은 안내 `.step-box`는 중복이라 뺐다.

**최종 9단계.** 1 Claude Code 설치(체크리스트 링크) → 2 Bun 설치 → 3 BotFather 토큰 → 4 플러그인 설치 → 5 토큰 등록 → 6 `--channels` 재실행 → 7 봇에 메시지 → 8 페어링 → 9 연결 확인.

**번호 동기화 지점 5곳.** `.mcp-steps`는 `counter-increment: mcp`로 번호를 매기고 각 `<ol>`이 인라인 `counter-reset: mcp N`으로 이어받는다. 단계를 끼워 넣으면 뒤쪽 `counter-reset` 값 전부와 본문 교차 참조(`3번에서 받은 토큰`, `5번 다음에 6번`, `6번 명령`, `8번 페어링 코드`)를 함께 밀어야 한다. 소요 시간 배지도 10분에서 15분으로, `필요한 것` 칩에도 `Bun`을 넣었다.

### 2026-08-26 (부록 신설: 컴퍼니 브레인 부활 + 점검과 운영 7가지)

전략 컨설턴트 워크샵용 부록 두 장을 만들었다. 인덱스 맨 끝에 `#section-brain`(배지 `부록`)을 신설했다.

**`company-brain.html`을 `backups/`에서 되살렸다.** 2026-07-12에 뺐던 파일이고 본문 골격(4역할·갱신 루프·폴더 구조·Claude Code 실행·검증 6항목·지식 그래프)은 그대로 살렸다. 부록 트랙이라 **step-nav를 뺐고**(`glossary`·`security-guide`와 같은 규약) `pages-brain` 2링크 내비로 바꿨다.

**정의가 없었다(사용자 지적).** `컴퍼니 브레인`이 제목에만 있고 본문에서 한 번도 정의되지 않은 채 시나리오로 시작했다. `.def-box`를 신설해 INTRO 첫 블록으로 넣었다. 사내 위키와 다른 두 가지, 곧 **쓰는 쪽도 먼저 읽는 쪽도 사람이 아니라 AI**라는 점을 정의의 중심에 뒀다.

**구조의 정본이 Karpathy `llm-wiki`임을 명시했다.** 2026-04-04 gist이고 공개 며칠 만에 5,000스타를 넘겼다. 원문 정의는 `raw`(불변 원자료)·`wiki`(LLM이 생성)·`schema`(규칙) 세 층과 `ingest`·`query`·`lint` 세 동작이다. **중요한 것은 방향이다. "사람이 AI가 읽기 좋게 쓰는 위키"가 아니라 "AI가 쓰고 유지하는 위키"다.** 이 페이지 4역할이 그 구현이므로 대응표를 넣어 이었다. 참고 자료 맨 앞에 gist를 추가했다.

**`wiki-config.md`를 6칸에서 7칸으로 늘렸다.** 03 자기완결 규칙을 신설하고 이후 번호를 밀었다. AI가 문서를 조각으로 잘라 읽으므로 `앞에서 본`·`위에서 말한`을 금지하고 **핵심 사실은 페이지마다 다시 적게 한다**. 사람 위키가 중복을 없애는 것과 정반대다. 4-B 프롬프트에도 같은 줄을 넣었다.

### 2026-08-14 (Ramp AI Index 2026년 7월 데이터 추가)

`orientation.html`의 기업 AI 도입률 차트를 42개월(2023-01 ~ 2026-06)에서 43개월(~ 2026-07)로 늘렸다. 7월 값은 Anthropic 43.46, OpenAI 39.7, Google 6.24, xAI 3.97, DeepSeek 0.25, Overall 55.73이다.

**월을 하나 추가하면 x축 눈금 좌표 15개가 전부 바뀐다.** 좌표가 `xAt(i) = 70 + i * (790 / (N - 1))`이라서 N이 42에서 43이 되면 칸 폭이 19.268에서 18.810으로 줄고, SVG에 손으로 박아 둔 분기 라벨(Jan·Apr·Jul·Oct)이 선과 어긋난다. 라벨과 연도 표기를 새 좌표로 다시 계산해야 한다. 2026-07은 i=42로 x=860에 정확히 떨어져 마지막 라벨을 `Jun`에서 `Jul`로 바꾸는 것으로 끝났다.

**오른쪽 끝 라벨은 자동이 아니다.** 끝 라벨 6개의 문구와 `y`, 연결 점선의 `y1`·`y2`를 값이 바뀔 때마다 손으로 맞춘다. `y = 410 - 값 * 5.5`가 선의 끝 좌표다. 이번에는 xAI가 3.03에서 3.97로 뛰어 선 끝이 5px 올라오면서 Google과 12.5px까지 좁아졌다. 라벨 자체는 14px 글자에 맞춰 18px 간격(377·395·413)을 유지하고, 연결 점선이 선 끝과 라벨 사이 차이를 잇는다.

**동기화 지점 4곳.** `series` 배열 6개와 `months` 배열, x축 라벨 15개, 오른쪽 끝 라벨 6개(`Overall 55.7%`·`Anthropic 43.5%`·`OpenAI 39.7%`·`Google 6.2%`·`xAI 4.0%`·`DeepSeek 0.3%`), `.ramp-context` 문장이다. 문장은 6월 기준 `42.4% 대 39.5%`를 7월 기준 `43.5% 대 39.7%로 격차가 3.8%p로 벌어지고 있습니다`로 바꿨다(사용자가 문장을 직접 줬다). 앞 문장의 `약 3배`는 7월 기준으로는 2.81배라서 `15.5%에서 2.8배로 올라섰고`로 고쳐 실제 값과 맞췄다. **브라우저 창 검증의 한계.** 이 창은 화면 아래쪽을 스크린샷으로 못 찍는다. 스크린샷은 navigate 직후 첫 화면만 반영하고 JS로 스크롤하거나 DOM을 고쳐도 그대로다. 창이 숨겨지면 `computer` 스크롤이 30초 뒤 타임아웃된다. 아래쪽 확인은 `javascript_tool`로 DOM 개수와 렌더 크기를 재는 방법을 쓴다.

### 2026-08-12 (빅3 전략 컨설팅펌의 AX 관점 페이지 신설, 진단에서 실행 순서까지)

`docs/ax-consulting-reports.html`을 만들었다. 인덱스 AX 사례 섹션의 `기업 AX 사례 준비 중` 카드 자리를 이 페이지가 대신한다(3칸 유지라 grid 수정 없음). 기업 사례 계획은 취소하지 않았고, 나중에 만들면 4칸으로 늘린다. 설계 스펙은 `specs/2026-08-12-mbb-ai-reports-design.md`에 있다.

**리포트를 모으지 않고 쟁점으로 세웠다.** 세 회사 링크는 검색하면 나온다. 값어치는 같은 질문 위에 셋을 나란히 놓을 때 생긴다. 서브메뉴 7탭은 `핵심 요약` + 쟁점 5개(`투자 규모와 배분`·`기대와 체감의 격차`·`성과 저해 요인`·`에이전트 전망`·`성숙도 진단 기준`) + `그래서 무엇을 하는가`다. 리포트가 갱신돼도 질문 축은 그대로 두고 셀만 바꾼다.

**중심은 s4다.** BCG는 거의 모든 CEO가 2026년 에이전트 수익을 기대한다고 적었고, 맥킨지는 약 3분의 2가 보안·리스크를 확장의 최대 장벽으로 꼽았으며 에이전트 거버넌스 성숙도 3 이상은 약 30%라고 적었다. 두 결과는 서로를 반박하지 않는다. **CEO에게 기대를 물은 조사와 거버넌스 담당자에게 준비를 물은 조사**라서 다르다. 이 구분을 해설로 붙였다.

**사용자 지적 두 건을 반영했다.** ① 탭 제목이 질문형(`돈은 얼마나 들어가는가`)이라 대화체였다. 전부 명사구로 바꿨다. ② 문제 제기만 있고 그래서 뭘 할지가 없어 짜깁기로 읽혔다. 쟁점마다 `.so-what`(오렌지 `그래서` 배지 + 행동 한 문장 + 해당 단계 링크)을 붙이고, 마지막 섹션을 링크 카드 6장에서 **실행 순서 5단계**로 교체했다. 각 단계는 `근거 수치` → `하는 일` → `이번 주에 할 일` → `가이드 링크` 네 칸이 같은 순서로 온다.

**순서 자체는 해석이라고 밝혔다.** 각 단계의 수치는 원문 확인값이지만 다섯 단계라는 배열은 이쪽 편집이다. s6 하단에 이 구분을 적었다. 밝히지 않으면 이 페이지가 지키려는 출처 원칙이 무너진다. 같은 이유로 3사가 사이트 주장을 **유보하는 대목도 실었다**. 에이전트를 1번이 아니라 5번에 둔 것도 근거를 따른 결과다.

**출처 확인은 브라우저로만 된다.** `bcg.com`·`web-assets.bcg.com`은 WebFetch 403, `mckinsey.com`은 타임아웃, `bain.com`은 대기 화면을 거친다. `openai.com`과 같은 처리가 필요하다. 확인 못 한 수치(맥킨지 State of AI의 88%·39% EBIT 등)는 넣지 않았다. 모든 수치와 원문 쪽지는 파일 상단 `DATA` 주석 블록에 있고 SVG가 그 값을 그대로 쓴다.

**차트 5종은 인라인 SVG다.** 라이브러리를 쓰지 않는다. 차트마다 `<figure>`+`<figcaption>`에 회사·리포트명·발행 연월·원문 링크를 알약으로 단다. 색만으로 구분하지 않도록 계열마다 이름을 직접 적었다.

**함정: `.cmp-board`의 행 수는 레일 개수와 반드시 맞아야 한다.** `grid-auto-flow: column`이라 어긋나면 칸이 다음 열로 밀려 표 전체가 뒤섞인다. 실제로 `cols-2`(원래 4행짜리 표에 쓰던 값)를 그대로 썼다가 표가 뒤섞였다. 최종 형태는 `cols-3`에 레일 8개라 `auto repeat(8, auto)`다. 레일을 더하거나 빼면 이 값도 같이 고친다. 검산은 `셀 개수 == 레일 개수 × 열 개수`.

**사실 검증.** openai.com과 help.openai.com이 WebFetch를 403으로 막아 브라우저로 직접 열어 확인했다. 1차 출처는 앤트로픽 `claude.com/product/cowork`·헬프센터 `Get started with Claude Cowork`, OpenAI `openai.com/chatgpt-work`(한국어 페이지)다. 확인한 사실은 이렇다. Cowork는 유료 플랜(Pro·Max·Team·Enterprise), 로컬 파일 직접 읽기와 쓰기, 데스크톱 앱이 켜져 연결돼 있어야 하고 웹·모바일은 베타다. ChatGPT Work는 GPT-5.6 기반, 맥·윈도우 데스크톱 앱은 모든 플랜이고 웹·모바일은 Plus·Pro·Business·Enterprise·Edu, 플러그인 1,400개 이상, Plan 모드로 계획을 승인받은 뒤 실행한다.

**주의: OpenAI의 워크스페이스 에이전트는 ChatGPT Work와 다른 제품이다.** 워크스페이스 에이전트는 팀이 공유 에이전트를 만들어 정해진 일정에 돌리는 Business·Enterprise·Edu 쪽 기능이다. 기사들이 두 이름을 섞어 쓰므로 요금제나 기능을 확인할 때 반드시 제품 이름을 구분한다. 이 구분은 `chatgpt-work.html`의 `헷갈리기 쉬운 이름` 박스에 적어 뒀다.

검증은 태그 균형·금지 표현·내부 링크 15개씩을 정적으로 확인하고, 비교표 그리드 좌표와 목업 크기를 브라우저에서 실측하는 방식으로 했다. 콘솔 오류 없음. 스크린샷은 브라우저 패널이 숨겨진 상태라 캡처하지 못했고 수치 검증으로 대신했다.

**배경 제거에서 허용치를 잘못 잡아 캐릭터 팔다리가 통째로 날아갔다.** 처음에는 색거리 62로 잡았는데, 배경 갈색이 기준색에서 6 이상 벗어나지 않는 반면 그늘진 주황 다리는 37~41밖에 떨어져 있지 않았다. 다리와 팔이 배경으로 분류돼 사라졌고, 사용자가 "클로드 로봇 다리와 팔이 없어지잖아"라고 지적해서야 원본과 나란히 놓고 확인했다. 허용치를 18로 낮춰 다시 뽑았다. 눈으로 보지 않고 120장을 돌린 것이 문제였다. 이후로는 초록·크림·표지 갈색 세 배경 위에 합성해 확인하고 나서 전체를 돌렸다.

가장자리 처리도 한 번 고쳤다. 잘라낸 경계 픽셀에는 원본 배경색이 섞여 있어 표지 위에서 테두리로 뜬다. 속을 2px 깎고 바깥을 가장 가까운 속 색으로 덮은 뒤 알파만 흐리는 방식으로 바꿔 없앴다.

**소스 영상이 도중에 바뀌었다.** 파스텔 배경의 `robot.mp4`로 한 번 완성한 뒤 사용자가 갈색 배경의 `robots.mp4`로 교체했다. 배경 성격이 다르면 후보 규칙을 다시 잡아야 한다. 파스텔본은 밝고 채도 낮은 픽셀을 후보로 삼는 규칙이었고, 갈색본은 배경이 거의 단색이라 기준색과의 거리로 바꿨다.

스크롤이 멈춘다는 제보를 받고 세 가지를 고쳤다. 캐로우절이 스스로 `scrollLeft`를 움직이는 동안 손가락 세로 스크롤이 취소되는 것, 메뉴·모달의 `body { overflow: hidden }`이 뒤로가기로 되살아나는 것, 그리고 표지가 화면에 붙어 있는 200svh 구간이다. 마지막 것은 스크롤이 먹기는 하는데 화면이 그대로라 멈춘 것처럼 보였다. 앞의 둘은 걷어냈고 표지는 140svh로 줄였다. 가로 스냅도 `mandatory`에서 `proximity`로 바꿨다.

인트로를 지우면서 모바일 문서 높이가 15799px에서 12871px로 줄었다. 인트로 프레임 69장도 모바일에서는 받지 않는다.

문구 두 곳도 함께 고쳤다. `모두의 무기로` → `모두의 생존 무기로`, `매주 업데이트 하고 있습니다. 새 모델이나...` → `매주 업데이트 하며, 새 모델이나...`.

검증은 데스크톱 1280·820, 모바일 390·360에서 DOM 수치로 했다. 제목이 판면을 넘지 않는지(1280에서 660px 대 803px, 360에서 270px 대 320px), 문서 끝까지 스크롤이 도달하는지, 가로 오버플로가 없는지, 캐로우절이 4.2초 동안 스스로 움직이지 않는지, 콘솔 에러가 없는지 확인했다.

### 2026-08-01 (목록으로 앵커 착지 복구)

사용자가 "콘텐츠 페이지에서 `← 목록으로`를 누르면 인덱스의 해당 섹션으로 가게 해달라"고 요청. 확인해 보니 링크는 이미 전부 맞았다. 콘텐츠 43개 페이지의 back-link와 모바일 드로어 링크가 모두 `index.html#section-N`을 가리키고, 인덱스 섹션 배치와도 일치했다. 문제는 받는 쪽이었다.

| # | 명령 | 범위 | 결과 |

**원인은 `html { scroll-behavior: smooth }`와 380svh 표지 구간의 조합이다.** 브라우저는 해시를 받으면 부드러운 스크롤을 시작하는데, 그동안 표지 영상과 폰트가 올라오며 문서 높이가 바뀌면 그 스크롤이 취소된다. 결과는 맨 위 인트로 화면이다. 링크만 보면 멀쩡해 보이니 href부터 고치려 들기 쉽다.

한 번만 맞추는 것으로는 부족했다. 첫 시도는 `load` 뒤 600ms에 한 번 자리를 잡고 끝냈는데, 그 다음에 레이아웃이 90px 밀려 섹션 제목이 스티키 내비 뒤로 숨었다. 높이가 굳을 때까지 계속 다시 맞춰야 한다.

검증은 로컬 서버에서 `section-1`·`section-4`·`section-glossary`로 각각 들어가 섹션 상단이 뷰포트 80px(`.card-section`의 `scroll-margin-top`) 지점에 서는지 DOM으로 확인했다. 해시 없이 들어오면 인트로가 예전대로 맨 위에서 재생된다.

이어서 클라이언트 대시보드 2종을 공개용으로 살렸다. 사용자가 "cases 밑 포스코·LG전자 대시보드를 메인 어딘가에 링크로 살리자, 클로드 코드 과제 8가지로 가야 하나"라고 물었다. **과제 8가지는 아니다.** 그 페이지는 독자가 직접 만드는 커리큘럼인데 이 대시보드는 재현할 재료(3년치 시장 데이터 6종)를 줄 수 없다. 성격이 맞는 자리는 갤러리 섹션이고, 대시보드 2번 섹션 제목이 그대로 `탐색적 분석 (EDA)`이라 `eda-gallery.html`과 같은 선반이다.

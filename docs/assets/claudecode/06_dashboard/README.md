# 06_dashboard · 피자 매장별 실적 데이터

바이브 코딩 실습 05(엑셀 실적 데이터로 시사점·PPT), 06(온톨로지·지식 그래프), 07(구글 스프레드시트 대시보드)이 쓰는 데이터 묶음입니다.

## 파일

| 파일 | 역할 |
|---|---|
| `데이터/피자 매장별 실적 데이터.xlsx` | 실습용 워크북. 원본 시트 1장 + 보조 시트 7장 |
| `build_practice_sheets.py` | 보조 시트 7장을 다시 만드는 스크립트. 원본 시트는 손대지 않음 |
| `extend_sales_data.py` | 매출데이터를 지정 월(END_YM)까지 전년 같은 달 × 최근 성장률로 연장. 2026-06~08은 이 스크립트로 만듦 |
| `build_dashboard_data.py` | 원본 시트(매출데이터)를 읽어 `dashboard.html`의 데이터 객체를 재생성 |
| `dashboard.html` | 완성 대시보드 샘플 |
| `데이터/dashboard_data.json`, `processed_data.json` | 대시보드용 중간 산출물 |

## 워크북 시트

| 시트 | 내용 | 행 |
|---|---|---|
| 안내 | 파일 목적, 세 가지 실습, 시트 구성, 알아 둘 점 | 24 |
| 매출데이터 | 원본. 9개 매장 × 2020-01~2026-08 × 매출카테고리 6종 | 4,326 |
| 데이터사전 | 39개 열의 뜻, 단위, 성격(개체 키·차원·지표·비율), 집계 단위 | 39 |
| 매장마스터 | 매장 9곳의 신·구 코드, 별칭, 도시, 권역, 지역본부, 점주, 개점일, 상권, 가맹유형, 담당SV | 9 |
| 메뉴마스터 | 메뉴 22개와 카테고리, 판매가, 구성 식자재(공급사 코드), 출시일, 단종일 | 22 |
| 공급사마스터 | 공급사 6곳과 품목, 계약, 리드타임 | 6 |
| 플랫폼마스터 | 배달앱 3곳과 자사앱의 수수료율, 계약, 매출데이터 열 대응 | 4 |
| 사건로그 | 2020~2026년 사건 39건. 본사 정책, 외부환경, 신메뉴, 플랫폼, 위생, 클레임, 인력, 리뉴얼, 데이터 오류 | 36 |

## 세 가지 실습이 이 구조를 쓰는 방식

1. 탐색적 분석 → 시사점 5개. 매출데이터를 매장·월로 중복 제거한 뒤 분석하고, 사건로그와 대조해 원인이 확인된 것과 추정인 것을 나눕니다.
2. 컨설팅 PPT. 시사점 5개를 액션 타이틀과 근거 차트로 옮깁니다.
3. 온톨로지·지식 그래프. 모든 시트를 읽고 개체 타입·속성·관계·규칙을 설계한 뒤 실제 개체를 연결합니다.

## 일부러 넣어 둔 함정

- 매장·월 단위 열이 카테고리 6행에 반복됩니다. 그대로 합치면 6배가 됩니다.
- 매장 식별자가 시트마다 다릅니다. 매출데이터는 매장명, 사건로그는 구코드(2022-08 이전)·신코드·약칭. 매장마스터가 대응표입니다.
- 배달수수료는 매출카테고리에 있지만 상품이 아닙니다.
- 둔산점 2026-01은 두 번 들어 있고(텍스트 날짜·정수 값 / 날짜 형식·소수 값), 2026년 값에는 소수가 섞여 있습니다.
- 사건로그 확인여부가 "추정"·"미확인"인 항목은 데이터로 검증해야 씁니다.

## 갱신

```bash
python3 build_practice_sheets.py           # 사건로그 수치가 데이터와 맞는지 검증
python3 extend_sales_data.py --write       # 매출데이터를 END_YM까지 연장(필요할 때만)
python3 build_practice_sheets.py --write   # 보조 시트 갱신
python3 build_dashboard_data.py            # 대시보드 데이터가 여전히 같은지 확인
```

사건로그에 숫자를 적을 때는 `verify()`에 대조 항목을 하나 추가합니다. 수치가 어긋나면 스크립트가 저장을 거부합니다.

구글 스프레드시트 실습(07)은 같은 데이터의 온라인 사본을 씁니다. 보조 시트를 온라인에도 반영하려면 이 워크북을 구글 시트로 가져오기 하면 됩니다.

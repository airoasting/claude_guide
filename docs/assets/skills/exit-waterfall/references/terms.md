# 우선주 조건을 계산 입력으로 옮기는 법

텀시트와 주주간계약의 문장을 `captable.json`의 필드로 바꾸는 대응표다. 조항 해석은 법률 자문의 몫이고, 이 문서는 숫자로 옮기는 자리만 다룬다.

| 계약서 표현 | 입력 필드 | 값 |
|---|---|---|
| 투자원금의 1배를 우선하여 분배 | `multiple` | 1.0 |
| 투자원금의 1.5배를 우선하여 분배 | `multiple` | 1.5 |
| 잔여재산 분배에 참가하지 아니한다 | `participating` | false |
| 보통주와 함께 잔여재산 분배에 참가한다 | `participating` | true |
| 총 분배액이 투자원금의 2배에 달할 때까지 | `cap_multiple` | 2.0 |
| 참가 한도를 두지 아니한다 | `cap_multiple` | null |
| 후행 시리즈가 선행 시리즈에 우선한다 | `seniority` | 후행일수록 작은 수 |
| 모든 종류주가 동순위로 분배받는다 | `seniority` | 전부 같은 수 |

## 자주 어긋나는 자리

**"1배 비참가"와 "1배 참가"는 완전히 다르다.** 비참가는 우선변제와 보통주 전환 중 유리한 쪽 하나를 고르는 것이고, 참가는 우선변제를 받고 잔여 배분에도 들어간다. 같은 1배라도 낮은 매각가에서 수령액이 두 배 가까이 벌어진다.

**참가 상한은 총 수령액 기준이지 잔여 배분 기준이 아니다.** 상한 2배는 "우선변제 1배 + 잔여 배분 1배까지"를 뜻한다. 잔여 배분에서 따로 2배를 더 받는다는 뜻이 아니다.

**희석방지는 이 계산기가 다루지 않는다.** 다운라운드가 있었다면 전환비율이 1대 1이 아니므로, 조정된 전환주식수를 `shares`에 직접 넣어야 한다. 조정 계산은 계약서의 산식(전면 래칫인지 가중평균인지)을 따른다.

**스톡옵션은 전량 행사를 가정한다.** 미행사분이 있으면 그만큼 `shares`에서 빼고, 뺐다는 사실을 산출물에 적는다.

## 입력을 만든 뒤 반드시 하는 것

```bash
python3 waterfall.py captable.json
```

출력의 각 시나리오에 "검산 일치"가 찍히는지 본다. 하나라도 불일치가 나오면 입력이 잘못된 것이다. 결과를 쓰지 말고 입력을 다시 본다.

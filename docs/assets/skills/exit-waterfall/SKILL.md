# 엑싯 워터폴 계산기

캡테이블과 우선주 조건을 넣으면, 매각 금액에 따라 누가 얼마를 가져가는지 계산하는 스킬이다.

## 이 스킬이 푸는 문제

지분율 표는 모두가 갖고 있지만, 그 표는 매각 시 분배를 알려주지 않는다. 청산우선권이 붙는 순간 지분율과 실수령액이 어긋나기 때문이다. 시리즈B가 지분 16.7%를 갖고도 400억 매각에서 40.8%를 가져가는 일이 실제로 일어난다.

문제는 이 계산이 손으로 하기 번거롭다는 데 있다. 각 우선주가 "우선권을 받을지, 포기하고 보통주로 전환할지"를 선택하고, 그 선택이 다른 주주의 몫을 바꾸며, 서로 물고 물리기 때문이다. 그래서 협상 자리에서는 대개 감으로 말한다.

이 스킬은 그 계산을 끝까지 돌린다.

## 입력

**필수**
- 주주별 보유 주식 수 (보통주, 종류별 우선주, 스톡옵션 풀)
- 라운드별 투자금액

**조건 (없으면 아래 기본값을 쓰고, 기본값을 썼다는 사실을 산출물에 명시한다)**

| 항목 | 기본값 |
|---|---|
| 청산우선권 배수 | 1배 |
| 참가 여부 | 비참가적 |
| 참가 상한 | 없음 |
| 우선순위 | 후순위 라운드 우선 (B → A → 시드) |
| 희석방지 | 계산하지 않는다. 다운라운드로 전환비율이 조정되었다면 조정 후 주식 수를 직접 넣는다 |

텀시트나 주주간계약 파일을 주면 조건을 읽어 채우고, 읽어낸 조항을 원문과 함께 표시해 사용자가 확인하게 한다.

## 참고 자산

`references/terms.md`에 텀시트 문구를 `captable.json` 필드로 옮기는 대응표와 자주 어긋나는 자리가 있다. 입력을 만들기 전에 읽는다.

## 계산은 스크립트로 한다

**손으로 계산하지 않는다.** 이 폴더의 `waterfall.py`를 쓴다.

```bash
python3 waterfall.py captable.json          # 표로 출력
python3 waterfall.py captable.json --json   # JSON으로 출력
python3 waterfall.py --selftest             # 계산기 자체 검증
```

입력 JSON 형식은 `captable.example.json`에 주석과 함께 있다. 사용자 캡테이블을 이 형식으로 옮긴 뒤 실행한다.

이 규칙을 두는 이유는 두 가지다. 첫째, 이 계산에는 사람이 반복해서 틀리는 자리가 정해져 있다.

1. 참가적 우선주의 지분은 우선변제를 받든 안 받든 **항상** 잔여 배분 풀에 들어간다. 빠뜨리면 배분 합계가 매각 대금을 넘는다.
2. 참가 상한에 닿으면 초과분을 나머지 주주에게 다시 나눠야 하고, 그 재배분이 다른 우선주의 전환 판단을 바꾼다.

둘째, `--selftest`가 검증된 기준값 대비 회귀를 잡는다. 세 시나리오의 주주별 배분액, 전환 분기점 3개, 참가 상한 도달 지점, 보통주 첫 수령 지점까지 확인한다. 스크립트를 고쳤으면 `--selftest`를 먼저 통과시킨 뒤 결과를 쓴다.

스크립트를 쓸 수 없는 환경이면 아래 규칙대로 계산하되, **검산이 맞지 않으면 결과를 내지 않는다.**

## 계산 규칙

**1. 우선변제**
우선순위가 높은 종류주부터 청산우선권 금액을 가져간다. 매각 대금이 우선변제 총액에 못 미치면 그 안에서 순위대로 나누고, 후순위와 보통주는 0이다.

**2. 잔여 배분**
- 비참가적 우선주는 우선변제를 받으면 잔여 배분에 참여하지 않는다
- 참가적 우선주는 우선변제를 받고 잔여 배분에도 참여한다. 지분은 항상 잔여 배분 풀에 포함된다
- 참가 상한이 있으면 총 수령액이 상한에 닿는 순간 멈추고, 남은 금액을 나머지 주주에게 다시 나눈다

**3. 전환 선택**
각 우선주는 우선권을 포기하고 보통주로 전환할 수 있다. 전환이 유리한지는 다른 주주의 선택에 따라 달라지므로, **모든 조합을 계산해 아무도 자기 선택을 바꿔 더 받을 수 없는 상태를 찾는다.** 이 상태 하나만 결과로 제시한다.

**4. 검산**
모든 시나리오에서 주주별 수령액의 합이 매각 대금과 일치하는지 확인한다. 일치하지 않으면 결과를 내지 않고 어느 단계에서 어긋났는지 보고한다. 이 검산을 건너뛰지 않는다.

## 산출물

워터폴 리포트 HTML 한 장.

1. 캡테이블과 적용 조건 요약 (기본값을 쓴 항목 표시)
2. 시나리오별 분배표 (금액, 지분율 대비, 투자 배수)
3. 분배 구성 막대 (각 시나리오에서 누가 얼마를 가져가는지 시각화)
4. 분기점 목록 (각 우선주가 전환으로 돌아서는 매각가, 참가 상한에 닿는 매각가, 보통주가 처음 돈을 받는 매각가)
5. 읽는 법 (이 캡테이블에서 무엇이 특이한지 두세 문장)
6. 계산 전제와 다루지 않은 것

시나리오는 사용자가 지정하지 않으면 세 개를 쓴다. 우선변제 총액 부근, 직전 라운드 밸류에이션 부근, 그 두 배 지점이다.

## 하지 않는 것

- 세금을 계산하지 않는다. 모든 금액은 세전이다.
- 거래 비용, 에스크로, 언아웃, 매도인 진술보장 관련 유보금을 반영하지 않는다. 반영하려면 사용자가 금액을 지정해야 한다.
- 텀시트 조항의 법적 효력을 해석하지 않는다. 조항을 숫자로 옮길 뿐이다.
- 매각을 권하거나 조건이 좋다 나쁘다 평가하지 않는다.
- 입력에 없는 라운드나 조건을 추정으로 채우지 않는다.

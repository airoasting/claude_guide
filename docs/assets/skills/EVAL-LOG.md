# VC/PE 스킬 5종 검증 기록

2026년 7월 31일. 각 스킬을 가장 깨지기 쉬운 경계 사례로 한 번씩 실행하고, 산출물을 검증 항목에 대조했다.

목적은 통과율이 아니었다. **스킬 문서에 적어 놓지 않은 빈자리를 찾는 것**이었다. 문서만 읽으면 규칙이 서로 부딪히는 자리가 보이지 않는다. 실제로 돌려야 보인다.

## 고친 것 중 남겨 둘 만한 넷

**1. 계산기가 없는 숫자를 지어내고 있었다 (exit-waterfall).**
`common_first_payment()`가 상한 검증 없이 이분 탐색만 했다. 정답이 탐색 범위 밖이면 상한값을 분기점으로 찍는다. 매각가 50억만 물었을 때 "보통주 첫 수령 200.00억"이 나왔고 정답은 210억이었다. 배분 합계 검산은 시나리오만 보고 분기점은 보지 않으므로 이 오류를 어디서도 잡지 못한다.

교훈은 **검산이 있다고 전부 검증된 것은 아니라는 점**이다. 검산이 덮지 않는 출력이 무엇인지 따로 확인해야 한다. 지금은 범위 밖 가드 3건을 자체 검증에 넣어 회귀를 막는다.

**2. 같은 지표의 정의가 문서마다 달랐다 (dd-redflag).**
이익의 질을 SKILL.md는 당기순이익, `thresholds.md`는 영업이익 기준으로 썼다. 같은 데이터에서 등급이 뒤집힌다. 재현성을 목적으로 만든 문서가 그 목적을 스스로 깼다. 기준선 문서를 새로 쓸 때는 **본문과 README의 같은 항목 서술을 함께 고쳐야 한다.**

**3. 자료 부족을 잡는 장치가 자료 부족에 무너졌다 (ic-memo).**
경고가 "미확인 비율 절반 초과"로만 발동해서, 숫자 자체가 적으면 비율이 낮아 오히려 경고가 꺼졌다. 비율 조건만 쓰는 경고는 분모가 작아질 때 반대로 동작한다. 섹션 단위 조건을 함께 걸었다.

**4. 법적으로 불가능한 계획이 나올 수 있었다 (value-creation-100day).**
경영상 해고는 근로자대표에 50일 전 통보가 필요한데, "첫 30일에는 조직 개편을 시작하지 않는다"와 겹치면 100일 완료가 산술적으로 불가능하다. 스킬이 이 충돌을 몰라서, 형식 검증만 통과하고 실행 못 할 계획이 나올 여지가 있었다.

## 유일한 실패

ic-memo의 "숫자에 표시가 붙는다" 항목. 표와 주요 진술에는 붙었으나 **계산으로 나온 값**(마진, 증감률, 반대 논거의 시나리오 손실액)에 빠졌다.

원인은 규정 공백이었다. "모든 숫자에 세 표시 중 하나"라고만 했지 파생값을 어떻게 볼지 정하지 않았다. **재료 중 가장 약한 표시를 이어받는다**로 정하고, 가정이 들어간 값은 재료가 모두 확인이어도 추정으로 두게 했다. 같은 규칙으로 `ic-memo/sample.html` 자신도 어기고 있던 것을 고쳤다.

## 다시 돌릴 때

각 스킬의 `evals/evals.json`에 프롬프트와 검증 항목이 있다. `last_run` 필드가 이번 실행 결과다. 스킬을 고친 뒤에는 같은 케이스를 다시 돌려 회귀를 확인한다.

exit-waterfall은 스크립트만으로 회귀를 잡을 수 있다.

```bash
python3 exit-waterfall/waterfall.py --selftest
```

## 아직 하지 않은 것

트리거 최적화(`skill-creator`의 `run_loop.py`)를 돌리지 않았다. 세션 안에서 인증 오류가 나서 인증된 터미널에서 직접 실행해야 한다. 이것은 스킬 내용의 품질이 아니라 **발동 정확도**를 다듬는 작업이다.
